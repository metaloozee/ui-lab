# Working variants

Use this branch when the user asks to compare variants or feel working prototypes. Keep the main skill's agreed brief and design-system constraints.

## 1. Define the comparison

Choose one coherent piece and one axis, such as structure, density, emphasis, type, voice, or motion. Default to three variants; build more only when requested. Name each by its direction and give it a distinct position on the axis. Keep unrelated choices alike.

Done when each variant answers the same brief differently and no two occupy the same position.

## 2. Build comparable candidates

Use the project's existing preview mechanism or an isolated temporary route. Give each variant independent state, the same realistic content, and the same intended dimensions. Show them side by side or through a simple switcher when space is limited.

Compose existing components and keep temporary files identifiable. Each candidate must support the behavior needed to judge its direction. Revise a direction that breaks accessibility or required functionality before comparison.

Done when every candidate renders, responds to relevant inputs, and has been inspected in the intended viewing conditions without console errors.

## 3. Let the user choose

Show each variant's axis position, when it fits, and its cost. Present no winner unless asked for a recommendation. Wait for the user's choice. For another round, explore new positions around the direction they preferred.

Done when the user selects a direction.

## 4. Promote the choice

Integrate the winner into the actual UI. Remove only temporary files and entries created for this comparison, keeping shared parts the winner uses. Search for discarded names and inspect the diff.

Done when the chosen UI runs in its real context and comparison artifacts are accounted for. Return to the main skill's climb setup.
